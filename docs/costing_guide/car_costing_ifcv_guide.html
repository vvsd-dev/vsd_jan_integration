1. Big picture — what problem we solve

Shipping cars from Japan creates many cost lines: duty, wharfage, shipping, inspection, service, etc. Some costs are known early as estimates; some arrive later as posted accounting entries (Journal Entry / Purchase Invoice).

The system separates those two moments cleanly:

Figure 1 — High-level flow: estimate first on Car Costing, then push real posted expenses via IFCV.

Remember: Car Costing = “what we expect this car to cost”. IFCV = “what was actually posted on the Import File, and how we share it across the cars”.

2. The two DocTypes (and when to use each)

Car Costing

  • One document per car (Item)
  • Linked to an Import File
  • TZ lines (TZS) + Japan lines (USD)
  • Header: M3, YEN, exchange rates
  • Formulas (e.g. Wharfage = Duty × 7%)
  • Used for projected costing

Import File Cost Voucher (IFCV)

  • One document per Import File
  • Loads all cars on that BL / invoice
  • Loads posted JE/PI expense lines
  • Distributes amounts to cars
  • On submit, can update Car Costings
  • Used for actual expense allocation
Question Use
I know duty / M3 / shipping estimate for this car Car Costing
Accounts posted a JV for shipping / TPA / inspection on this Import File IFCV
One invoice for the whole BL must be split to 7 cars IFCV (By BL Equal or By BL M3)
Each car has its own journal (e.g. TRA Duty per chassis) IFCV (By Vehicle Manual)

4. Expected vs Actual (from your expense list)

Your spreadsheet separates Expected (how Car Costing thinks) from Actual (how accounting posts). That mismatch is exactly why IFCV exists.

Figure 3 — Your expense list: yellow = Fixed, blue = Variable/BL formulas, green = Inspection (MKT), orange = repairs.

Key idea: Clearing Container / Wharfage / TPA / ICD / Shipping are often estimated per car, but the actual JV/invoice is posted once for the whole BL. IFCV takes that BL total and divides it back to cars (Equal or M3).

6. Import File Cost Voucher (IFCV) — actuals from JE/PI

When you select an Import File, IFCV automatically loads:

  1. Vehicles — Items whose custom_bl matches Import File BL (else supplier invoice no).
  2. Expenses — Submitted Journal Entry debit lines + Purchase Invoice item amounts for that Import File.
Stock In Hand is ignored. Those PI lines are the car purchase (YEN stock), not distributeable landed expenses.

7. How money is split: Equal / M3 / Manual

Figure 7 — Three distribution methods on IFCV expense rows.

Manual dialog (what the user sees)

  1. Open IFCV → Actions → Distribute Manually
  2. Pick an expense row (only rows set to By Vehicle Manual)
  3. Optional: Quick: put full amount on one car
  4. Or type amounts per chassis until Remaining = 0
  5. Click Apply
If the Journal Entry remark contains a chassis number (e.g. RT1-1006295 | HONDA…), IFCV auto-puts the full amount on that car — Remaining shows TZS 0.00 in green.

9. What to click in Desk (user checklist)

A. Review projected Car Costing

  1. Desk → Car Costing list → filter Import File = N.TAN039/26MSC
  2. Open e.g. Noah CC-2026-00023
  3. Check TZ lines, Japan lines, M3, summary COST
  4. Do not confuse Excel “COST” (includes tax from selling price) with our landed COST

B. Work an IFCV

  1. Desk → Import File Cost Voucher → open IFCV-2026-00001 (or New)
  2. Select Import File → tables auto-load (or Actions → Reload from Import File)
  3. Scan Expenses: Costing filled? Distribution method correct?
  4. For Manual rows: Actions → Distribute Manually
  5. Confirm Total Expense Amount = Total Allocated Amount
  6. Submit when business is ready to push into Car Costings

C. If Costing is blank on an expense

Open that Costing and set Account to the same GL account used on the JE/PI. IFCV matches by account name. Example: Inspection head → Inspection JPY - JIL.
